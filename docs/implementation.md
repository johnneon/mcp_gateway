# Что сделать и в каком порядке

База шлюза без конкретных коннекторов. Коннекторы и журнал — в `docs/roadmap.md`.

Шлюз сам является MCP-сервером. Коннектор — модуль в коде с описанием полей аккаунта, проверкой соединения, инструментами и разрешёнными хостами. Клиент инструменты не добавляет.

Каждая задача закрывает один кусок, который можно проверить отдельно. Автотест идёт на фейке, без живого сервиса. Если задача меняет экран интерфейса, её ещё проходят через браузер.

```text
процесс и хранилище
        |
        v
конфигурации и пустой MCP
        |
        v
интерфейс (только то, что API уже умеет)
        |
        v
контракт коннектора, вид native
        |
        v
вид proxy
```

Имена переменных окружения в спецификации не заданы. [ПОД ВОПРОСОМ] до дизайна эпика 1: `MCP_HOST`, `MCP_PORT`, `ADMIN_HOST`, `ADMIN_PORT`, `DATA_DIR`, `ENCRYPTION_KEY`.

## 1. Процесс и хранилище

Исход: процесс стартует на двух портах, состояние живёт в одном зашифрованном файле.

| Задача | Что закрывает | Как проверить |
| --- | --- | --- |
| 1.1 Старт | Нет обязательной переменной — процесс не стартует и печатает имя, не значение. Есть переменные — слушает оба адреса из окружения, интерфейс по умолчанию на `127.0.0.1` | Запуск с одной пропущенной переменной |
| 1.2 Хранилище | Файла нет — пустое состояние. Запись через временный файл и переименование, по очереди. На диске нет открытого текста. Чужой ключ или битый файл — процесс не стартует, причина без ключа и содержимого | Повторный старт, чтение файла, старт с другим ключом |
| 1.3 `GET /health` | На порту MCP без аутентификации: статус процесса, без каталога и секретов | HTTP без bearer |
| 1.4 Разделение портов | Порт MCP отвечает только на `/mcp` и `/health`, остальное 404. Порт интерфейса не отвечает на MCP | Запросы к обоим портам |

## 2. Конфигурации и MCP

Исход: оператор управляет конфигурациями по HTTP, MCP-клиент с bearer получает пустой `tools/list`.

| Задача | Что закрывает | Как проверить |
| --- | --- | --- |
| 2.1 API конфигураций | Создать (токен один раз, в хранилище только SHA-256), список без токена, ротация (старый bearer сразу мёртв), выключение, удаление | API интерфейса |
| 2.2 Защита API | Изменение без `Content-Type: application/json` — отказ. Заголовков CORS нет | Запрос с формой и с JSON |
| 2.3 MCP | Верный bearer, Streamable HTTP, пустой `tools/list`. Пустой, неизвестный и выключенный токен — один отказ, без списка конфигураций | MCP-клиент в тесте |

Галочки аккаунтов в этом эпике не появляются: аккаунтов ещё нет.

## 3. Интерфейс

Исход: те же действия в английском интерфейсе. Входа нет.

| Задача | Что закрывает | Как проверить |
| --- | --- | --- |
| 3.1 Configurations | Список, создание, токен один раз, ротация, выключение, удаление | Экран |
| 3.2 Connectors | Экран есть, коннекторов в поставке нет — пустое состояние | Экран |

## 4. Контракт коннектора, вид `native`

Исход: новый коннектор подключается модулем в коде. В поставке список пуст. Тест доказывает контракт фейковым коннектором, без живого сервиса.

| Задача | Что закрывает | Как проверить |
| --- | --- | --- |
| 4.1 Контракт | id, имя, поля (`text`, `secret`, `host`), проверка, разрешённые хосты, вид. Поле `host` — только имя хоста | Фейковый коннектор |
| 4.2 Аккаунт | Сохраняется только после проверки. Секретные поля в ответ API не попадают. Пустое секретное поле при правке — «не менять». Выключение и удаление, удалённый пропадает из конфигураций | API и фейк |
| 4.3 Форма аккаунта | Экран Connectors строит форму по описанию полей. Секретов на экране нет | Экран |
| 4.4 Выдача | Галочки аккаунтов на конфигурации | API и экран |
| 4.5 `tools/list` | Инструменты `<id>_<имя>` только для коннекторов с доступными аккаунтами. В схеме `account` — id и подписи только этих аккаунтов | Две конфигурации: с аккаунтом и без |
| 4.6 `tools/call` | Вызов идёт в обработчик. Чужой или выключенный `account` — отказ, у фейка 0 соединений. Сеть только на разрешённые хосты, редирект на чужой хост не выполняется | Счётчик фейка |
| 4.7 Ошибки и секреты | Короткий английский текст. Секрет из фикстуры не попадает в ответ и ошибку MCP. Таймаут и предел размера — константы в коде | Фейк обрывает, раздувает ответ, возвращает секрет |

## 5. Вид `proxy`

Исход: сторонний MCP-сервер по stdio подключается как коннектор. Тест идёт на фейковом MCP-сервере.

| Задача | Что закрывает | Как проверить |
| --- | --- | --- |
| 5.1 Запуск | Процесс на аккаунт при первом вызове, остановка после простоя, перезапуск после падения | Фейк считает запуски |
| 5.2 Окружение | Только сопоставленные поля аккаунта и минимум для запуска. Ключа шифрования и других переменных шлюза нет | Фейк сообщает своё окружение |
| 5.3 Инструменты | Наружу только разрешённые, с префиксом и параметром `account`. `account` до дочернего процесса не доходит | `tools/list` и аргументы в фейке |
| 5.4 Секреты | Секрет в ответе фейка вырезан. stderr клиенту не отдаётся | Фейк возвращает секрет и пишет в stderr |

Дальше каждый эпик оформляется отдельным предложением OpenSpec. Реализация эпика начинается только после принятого предложения.
