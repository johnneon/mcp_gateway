# MCP Gateway

The gateway stores connector credentials and exposes MCP to clients. Code defines the tool list. A client proves access with a bearer token. The model never receives a connector secret.

## Stack

One Node.js 22 process, TypeScript.

- `server` — MCP Streamable HTTP (`@modelcontextprotocol/sdk`), admin API, SQLite, connectors.
- `web` — React and Vite. No UI kit and no separate frontend service. The same process serves the static build.
- Connector secrets in SQLite are encrypted (AES-GCM). The key comes only from the environment. If a required variable is missing, the process exits and prints the variable name, not the value.

## Laws

- Only the process sees a connector secret, the encryption key, and the raw bearer. The database stores the bearer as a hash.
- A client bearer does not open the admin UI. An admin session does not call MCP.
- Model arguments contain no URL, host, or secret. The host is fixed in the connector code.
- Admin UI copy, tool names, tool descriptions, and MCP error text are English.
- A new connector is a new OpenSpec change plus code. Do not build a runtime tool catalog.

## Truth

| Layer | Where | When |
| --- | --- | --- |
| Product vision | `mcp-gateway-spec.md` | Source of changes. Not edited during apply |
| Task contract | `openspec/changes/<name>/` | Accepted proposal, delta specs, design, tasks |
| System behavior | `openspec/specs/` | After archive |

When the vision and the accepted delta disagree, the delta wins for the duration of the change.

## Cycle

Cursor commands: `/opsx-propose`, `/opsx-apply`, `/opsx-verify`, `/opsx-archive`. Repository CLI: `npx openspec`.

1. The developer proposes a change and stops. This step writes no product code.
2. A person edits the artifacts and asks for implementation in a separate request.
3. The developer completes the tasks.
4. The validator checks the change in a clean context: spec, leaks, e2e. The validator does not edit the product.
5. Commit only when a person asks, and only if the validator report has no blockers.
6. Archive merges the delta into `openspec/specs/`.

The session that wrote the code does not declare the change accepted.

## Roles

- `/developer` — propose and apply. Skills: `backend`, `frontend`, `tests`, `commits`.
- `/validator` — verify, review, and e2e. Skills: `code-review`, `e2e`, `openspec-verify-change`.

OpenSpec skills live in `.cursor/skills/openspec-*` and are generated by the CLI. Do not edit them by hand. Project skills live in `.cursor/skills/` and do not use the `openspec-` prefix.

## Done

A change is ready to archive only when all of these are true:

- every item in `tasks.md` is checked;
- `npx openspec validate` passes;
- delta scenarios are covered by automated tests and those tests pass;
- e2e for the affected scenarios has passed;
- `.harness/reports/<change>.md` exists and lists no blockers.
